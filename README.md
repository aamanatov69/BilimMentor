# BilimMentor

BilimMentor — MVP обучающей системы (LMS) на Node.js + Next.js + React + Tailwind CSS + shadcn/ui.

## Структура

- `api` — backend API (Node.js, Express, TypeScript)
- `auth` — Next.js: вход, регистрация и кабинеты студента, преподавателя и администратора
- `docs` — архитектурная и продуктовая документация

## Быстрый старт

### 1) API

```bash
cd api
npm install
npm run dev
```

Перед запуском заполните переменные в `api/.env`:

- `DATABASE_URL`
- `JWT_SECRET`
- `PORT`
- `CORS_ALLOWED_ORIGINS`
- `SMTP_HOST`
- `SMTP_PORT`
- `SMTP_USER`
- `SMTP_PASS`
- `SMTP_FROM`
- `FRONTEND_URL` или `NEXT_PUBLIC_APP_URL`

Для production:

- Используйте надежный `JWT_SECRET` (без fallback значений)
- Установите `MAILER_ALLOW_FALLBACK=false`
- Укажите production-домен(ы) в `CORS_ALLOWED_ORIGINS` через запятую
- Применяйте миграции командой `npm run prisma:migrate:deploy`

API будет доступно по адресу `http://localhost:4000`.

### 2) Auth

```bash
cd auth
npm install
npm run dev
```

Приложение будет доступно по адресу `http://localhost:3000`.

В `auth/.env` задайте `NEXT_PUBLIC_API_URL=http://localhost:4000` и `JWT_SECRET`, совпадающий с секретом API. Для PostgreSQL укажите рабочий `DATABASE_URL` в `api/.env`. После установки зависимостей API выполните `npm run prisma:generate`, затем примените миграции командой `npm run prisma:migrate:deploy` к подготовленной базе.

Штатный seed удаляет старые демонстрационные записи. Не запускайте его для создания тестовых аккаунтов в базе с нужными данными.

## Проверка запуска

- `GET /health` проверяет, что API отвечает, но не проверяет базу.
- `GET /ready` выполняет `SELECT 1`: возвращает 200 при доступной БД или 503 при ошибке/тайм-ауте. Это не проверка актуальности миграций.
- В `auth`: `npm run test:smoke` проверяет публичные страницы и `/health`; `npm run test:ready` дополнительно требует доступности БД.
- В обоих приложениях: `npm run typecheck`. В `api`: `npm test`. В `auth`: `npm run test:api-client` и `npm run test:upload` (Node.js 22.6+).

При ошибке PostgreSQL `28P01` исправьте учётные данные в `DATABASE_URL` и перезапустите API. Пароли не добавляйте в Git.

Для проверки подключения без запуска сервера выполните `npm run db:check` из папки `api`. Команда выполняет только `SELECT 1`, не изменяет данные и не выводит пароль или строку подключения. Успешная проверка подключения не подтверждает актуальность миграций.

## Обновление сессий и последнего урока

После обновления токенов пользователям нужно войти заново. API отзывает старые сессии при смене или сбросе пароля. В открытом кабинете повторный вход сохраняет состояние формы; действие после входа нужно повторить вручную.

Для сохранения последнего просмотренного урока примените миграции: в `api` выполните `npm run prisma:migrate:deploy`, затем `npm run prisma:generate` и перезапустите API. Миграция `20260925000000_last_viewed_lesson` добавляет два nullable-поля Enrollment, не удаляя данные. До применения миграции новая версия API не должна развёртываться для пользователей.

После восстановления БД можно выполнить `npm run create:test-users` в `api`: команда создаёт отдельные QA-аккаунты трёх ролей, показывает новые случайные пароли и не меняет существующие аккаунты. Текущий seed для этой задачи не использовать.

В `auth`: `npm run test:unit` запускает все локальные тесты; `npm run test:browser` проверяет интерфейс в Chrome/Edge с подменённым API и отдельным профилем (требуется запущенный frontend). Эти тесты не проверяют реальную БД. Артефакты сохраняются в `.browser-tests`, каталог исключён из Git.

## Вложения в ответах на задания

До 8 МБ на файл и 20 МБ суммарно. API принимает JSON до 30 МБ с учётом увеличения размера файлов при кодировании Base64. Превышение размера запроса возвращает HTTP 413, некорректный JSON — HTTP 400. Повреждённые вложения отклоняются; введённый ответ в открытой форме сохраняется при ошибке отправки.
