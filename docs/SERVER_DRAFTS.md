# Серверные черновики

## Область

Черновик редактора курса и черновик ответа студента сохраняются отдельно от опубликованного курса и отправленной работы. Сохранение черновика не создаёт курс, урок, оценку или отправленную работу. Локальные данные нельзя автоматически переносить между аккаунтами.

## Модель

`Draft`: UUID, ownerId (FK User, CASCADE), kind (`course_editor`/`assignment_answer`), targetId (nullable), payload (JSON), version (int), createdAt, updatedAt. Уникальный ключ ownerId/kind/key; для нового курса нужен постоянный UUID редактора вместо общего `new`. Вложения хранятся отдельно в объектном хранилище, в payload — только ссылки и метаданные. Пароли, токены и Base64 файлов в payload не сохраняются. Предлагаемый предел JSON — 1 МБ, срок хранения — 90 дней с предупреждением до удаления.

## API и права

- GET `/api/drafts/:id`: только владелец; сервер повторно проверяет доступ к курсу/заданию.
- POST `/api/drafts`: создать черновик для текущего пользователя; ownerId из сессии, не тела запроса.
- PUT `/api/drafts/:id`: обязательная ожидаемая version; атомарное обновление по ownerId/id/version. При расхождении — 409 с актуальной версией, без перезаписи.
- DELETE `/api/drafts/:id`: только владелец; успешная отправка/публикация удаляет использованную версию черновика в одной транзакции. Более новая версия сохраняется.

## Редактор

После загрузки сравнить локальный и серверный черновики, предложить восстановление с датами. При конфликте показать выбор версии и возможность скопировать текст. Сохранять через 1 секунду без изменений, не более одного запроса одновременно; отправлять следующий снимок после завершения предыдущего. Индикаторы: «Есть изменения», «Сохранение», «Сохранено» с датой, «Не сохранено» с повтором. При 401 повторный вход сохраняет состояние формы; никакой автоматической повторной отправки работы. Отображать предупреждение при внутренних переходах, если текущие изменения не подтверждены сервером.

## Проверки перед внедрением

Два устройства, конфликт версий, потеря сети, смена пользователя, отзыв доступа, истечение сессии, превышение лимита, удаление курса, отправка работы во время автосохранения. Миграция только добавляет таблицы. Развёртывание и внедрение API остаются отдельным этапом: текущий проект использует локальный черновик курса и состояние формы ответа.
